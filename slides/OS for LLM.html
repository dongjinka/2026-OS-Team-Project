01 · Fair scheduling

Real CFS scheduling, inside the kernel

Who gets the CPU when agents compete? Whoever has used it least, weighted by priority.

Weights
Linux’s 41-weight table
Priorities −20…20, ported verbatim — integer math only, since xv6 has no float and no heap.
Selection
Array scan, not a red-black tree
A simple O(n) scan finds the lowest vruntime, just as the assignment asked.
Guarantee
No starvation
A cfs_min_vruntime floor means even the lowest priority always gets a turn.

02 · The sandbox

Human input free, every AI command jailed

Why trust the AI? We don’t — three layers, enforced by the kernel’s code path.

L1
Deny-list
{KILL, EXEC} — humans extend it; the kernel rejects any edit from an agent process
L2
Blocked syscalls
Kernel refuses exec · kill · mknod for agent-role processes
L3
chroot jail
Locked folder — outside files invisible, every .. above the root refused
agent@agentbox $ cat notes.txt
remember to water the plants
agent@agentbox $ cat ../host/secret.key
denied · path escapes /agentbox
agent@agentbox $ exec sh
denied · syscall blocked for agent role
Role-based sandboxing · enforced by code/agentbox chroot jail
